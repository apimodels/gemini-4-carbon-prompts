# 44% prompt-cache hit rate for Factory-hosted gemini-4-carbon

Gemini 4 Carbon case 206 of 223 · Apps, Real Codebases and Tooling · [简体中文](#中文)

By marovole · [original GitHub page](https://github.com/Factory-AI/factory/issues/96) · 2026-11-12 · [see it in the apimodels.app gallery](https://apimodels.app/gemini-4-carbon-prompts/code)

- **What it is:** In a 4,392-message Droid session with 29 compactions on 2026-11-11, Factory-hosted gemini-4-carbon cached only 44.4% of input (184.3M uncached vs 147.0M cache-read tokens). The same model via BYOK the same day cached at 88.9%, and other hosted models at 96-99%.
- **Where:** GitHub
- **Tool:** Droid CLI 0.250.0 + Factory desktop, Max plan
- **Numbers the author reported:** 184.3M uncached input vs 147.0M cache-read tokens (44.4%) · 4,392-message session with 29 compactions · BYOK cached at 88.9% · other hosted models 96-99%
- **Prompt:** not published here. We do not reconstruct unpublished prompts.

To run Carbon yourself: [how to use Gemini 4 Carbon](https://apimodels.app/how-to-use-gemini-4-carbon) covers where it works, the settings that matter and what it costs.
